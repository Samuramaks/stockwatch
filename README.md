# stockwatch
# Запуск stockwatch на Windows с нуля

## Что понадобится

Нужны Windows 10 или 11 (64-бит), права администратора, интернет и около 40 минут. Go, PostgreSQL и редактор ставятся с нуля. Visual Studio Code не нужен: файл настроек правится в Блокноте.

Порядок: Go, проект, PostgreSQL, база и данные, файл `.env`, запуск, проверка.

## Шаг 1. Установите Go

1. Откройте https://go.dev/dl/ и скачайте установщик для Windows (файл вида `go1.26.x.windows-amd64.msi`). Для Windows на процессоре ARM выберите `windows-arm64`.
2. Запустите его и во всех окнах нажимайте Next, затем Install и Finish. Настройки менять не нужно.
3. Закройте все окна терминала. Go станет виден только в новых окнах.
4. Нажмите Win+R, введите `powershell` и нажмите Enter. Выполните `go version`. Должна появиться строка вида `go version go1.26.x windows/amd64`. Если команда не найдена, перезагрузите компьютер и повторите.

## Шаг 2. Распакуйте проект

1. Скопируйте `stockwatch.zip` на диск C:.
2. Нажмите на архив правой кнопкой, выберите «Извлечь всё…» и в строке пути укажите `C:\stockwatch`.
3. Откройте эту папку и найдите файл `go.mod`. Папка, в которой он лежит, дальше называется папкой проекта. Если `go.mod` оказался во вложенной папке `stockwatch`, папкой проекта считайте её.

Путь к папке проекта не должен содержать пробелов и русских букв.

## Шаг 3. Установите PostgreSQL

1. Откройте https://www.postgresql.org/download/windows/, нажмите «Download the installer», выберите версию 18.7 и Windows x86-64.
2. Запустите скачанный файл (нужны права администратора) и пройдите мастер: папки оставьте по умолчанию; компоненты PostgreSQL Server, pgAdmin 4 и Command Line Tools оставьте отмеченными (Stack Builder можно снять); порт оставьте 5432; локаль Default locale.
3. Когда мастер попросит пароль суперпользователя `postgres`, придумайте пароль **только из латинских букв и цифр** и запишите его: он понадобится в шаге 5.
4. В конце снимите галочку запуска Stack Builder и нажмите Finish.

## Шаг 4. Создайте базу и загрузите данные

1. Запустите pgAdmin 4 из меню «Пуск». Если он предложит придумать мастер-пароль, введите любой и запомните: он нужен только самому pgAdmin и с проектом не связан.
2. Слева раскройте Servers, дважды нажмите на PostgreSQL 18 и введите пароль из шага 3.
3. Раскройте Databases, нажмите правой кнопкой на базу `postgres` и выберите Query Tool.
4. Вставьте команду `CREATE DATABASE stockwatch WITH ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;` и нажмите F5. UTF-8 нужен, чтобы русский текст сохранялся без искажений. Внизу должно появиться сообщение об успешном выполнении.
5. Нажмите правой кнопкой на Databases и выберите Refresh: появится база `stockwatch`. Окно pgAdmin можно оставить открытым.
6. Откройте PowerShell в папке проекта (как в шаге 5), выполните команду `& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -h localhost -U postgres -d stockwatch -f db\stockwatch_dump.sql` и введите пароль пользователя `postgres` из шага 3 (символы при вводе не отображаются). 
7. В окне побегут строки `SET`, `CREATE TABLE`, `COPY` и `ALTER TABLE`, а также сообщения `NOTICE`: это нормально. Дамп уже содержит тестовые данные (четыре принтера и четыре позиции склада), отдельно ничего загружать не нужно. Если появилась строка с `ERROR`, то сообщите.
8. Проверьте: слева раскройте `stockwatch`, затем Schemas, public, Tables (при необходимости Refresh). Должны быть таблицы `printers`, `printer_statuses` и `stock_items`.

## Шаг 5. Настройте файл .env

Токен бота и id чата в файле уже заполнены. Вам нужно вписать только пароль от PostgreSQL.

1. Положите полученный файл `.env` в папку проекта рядом с `go.mod`.
2. В Проводнике включите показ расширений: Вид, Показать, Расширения имён файлов. Убедитесь, что файл называется `.env`, а не `.env.txt`.
3. Откройте папку проекта в Проводнике, нажмите на адресную строку, введите `powershell` и нажмите Enter. Окно PowerShell откроется в этой папке. Если файл назывался `.env.txt`, выполните `ren env.txt .env`.
4. Выполните `notepad .env`. Откроется Блокнот.
5. В строке `DATABASE_URL` замените `YOUR_POSTGRES_PASSWORD` на пароль PostgreSQL из шага 3. Сохраните файл (Ctrl+S) и закройте Блокнот.

Файл выглядит так:

```
DATABASE_URL=postgres://postgres:YOUR_POSTGRES_PASSWORD@localhost:5432/stockwatch?sslmode=disable
TELEGRAM_TOKEN=<заполнено>
TELEGRAM_CHAT_ID=<заполнено>
POLL_INTERVAL=30m
TONER_THRESHOLD=15
ALERT_COOLDOWN=24h
MAX_CONCURRENT=10
POLL_TIMEOUT=15s
```

Правила: без пробелов вокруг `=`, без кавычек, без комментариев в конце строк. Остальные строки менять не нужно: `POLL_INTERVAL` задаёт, как часто опрашиваются принтеры, `TONER_THRESHOLD` порог тонера в процентах, `ALERT_COOLDOWN` как часто можно повторять алерт по одному принтеру.


## Шаг 6. Запустите сервис

1. В PowerShell в папке проекта выполните `go run ./cmd/server`.
2. При первом запуске Go скачает библиотеки проекта: нужен интернет, это может занять несколько минут.
3. Если Windows покажет окно Брандмауэра с запросом доступа, нажмите «Отмена»: для работы на этом компьютере доступ из сети не нужен.
4. В журнале должна появиться строка `Authorized on account` и имя бота: токен принят. Рядом могут быть технические строки с `Endpoint: getMe`, это нормально. Через 10–15 секунд появятся строки «опрос не удался» по тестовым принтерам и итоговая строка «опрос завершён». Это ожидаемо: тестовых адресов не существует.
5. Строки «сервер запущен» нет. Если в журнале нет ошибок, сервер работает. Окно закрывать нельзя: сервис работает, пока оно открыто. Остановить его можно сочетанием Ctrl+C.

## Шаг 7. Проверьте работу

Откройте в браузере http://localhost:9091/.

- Вкладка «Принтеры»: список принтеров с уровнем тонера и остатком картриджей. У принтера, который ещё не опрашивался, написано «Ещё не опрашивался».
- Вкладка «Расходники»: нажмите «−1», число уменьшится; введите число в поле и нажмите «Добавить», остаток увеличится.
- Кнопки «Добавить принтер» и «Новый расходник» создают новые записи.

В дампе уже есть четыре принтера и четыре позиции склада, поэтому страница не пустая.

## Проверка алерта в Telegram

Для неё нужен принтер, доступный с вашего компьютера по SNMP (UDP 161). Тестовые адреса из дампа для этого не подходят.

1. Узнайте у администратора сети IP принтера и его SNMP community (часто `public`).
2. На странице нажмите «Добавить принтер» и заполните поля. В поле картриджа укажите SKU из вкладки «Расходники», например `TK-1170`.
3. В `.env` временно поставьте `TONER_THRESHOLD=100`: тогда любой уровень тонера считается низким. Остановите сервис (Ctrl+C) и запустите снова: проверка выполняется сразу при старте.
4. Через несколько секунд в Telegram-чат придёт сообщение с уровнем тонера и остатком картриджей на складе. Если принтер не ответил, в журнале будет строка с причиной по этому принтеру.
5. Верните `TONER_THRESHOLD=15`. Повторное сообщение по тому же принтеру не придёт в течение 24 часов. Чтобы проверить ещё раз, выполните в Query Tool базы `stockwatch` команду `UPDATE printer_statuses SET last_alerted_at = NULL;`.

## Остановка и удаление

Остановите сервис сочетанием Ctrl+C. Чтобы всё убрать: удалите папку проекта, удалите PostgreSQL и Go через «Параметры → Приложения».

## Если что-то не работает

| Симптом | Что делать |
| --- | --- |
| `go` не распознаётся | закройте PowerShell и откройте заново; если не помогло, перезагрузите компьютер |
| `no Go files` или «cannot find main module» | вы не в папке проекта: выполните `cd C:\stockwatch` |
| Ошибка про конфигурацию при старте | в списке будет сказано, какая переменная неверна. Проверьте `.env`: нет ли пробелов вокруг `=` и кавычек, лежит ли файл рядом с `go.mod` под именем `.env` |
| `password authentication failed` | в `DATABASE_URL` неверный пароль: нужен пароль из шага 3 |
| `database "stockwatch" does not exist` | пропущен пункт 4 шага 4 |
| `relation "printers" does not exist` | не загружен `stockwatch_dump.sql` |
| `connection refused` к базе | служба PostgreSQL не запущена: Win+R, `services.msc`, найдите postgresql-x64-16 и запустите |
| Go не скачивает библиотеки, `x509` или таймаут | корпоративный прокси или проверка сертификатов: обратитесь в ИТ или попросите автора приложить к проекту папку `vendor`, тогда скачивание не потребуется |
| Бот не авторизуется, таймаут | нет доступа к `api.telegram.org` из вашей сети |
| `chat not found` при отправке алерта | неверный `TELEGRAM_CHAT_ID` или бот не добавлен в чат |
| Порт 9091 занят | сервис уже запущен в другом окне PowerShell: закройте его |
| В журнале «timeout» по принтеру | принтер выключен, SNMP отключён, неверный community или блокируется UDP 161 |

## Для службы информационной безопасности

Сетевые взаимодействия:

| Направление | Порт | Куда | Зачем |
| --- | --- | --- | --- |
| Входящее | TCP 9091 | слушает на всех интерфейсах | веб-страница и HTTP API, без авторизации и без шифрования |
| Исходящее | UDP 161 | принтеры | опрос по SNMP v2c, community передаётся открытым текстом |
| Исходящее | TCP 443 | api.telegram.org | отправка алертов |
| Исходящее | TCP 443 | proxy.golang.org, sum.golang.org | скачивание библиотек при первой сборке |
| Локальное | TCP 5432 | localhost | PostgreSQL |

Данные и секреты:

- В базе лежат названия и IP-адреса принтеров, их SNMP community и складские остатки. Шифрования на уровне приложения нет.
- В `.env` пароль базы и токен бота хранятся открытым текстом. При сбое сети ошибка клиента Telegram может попасть в журнал вместе с адресом запроса, а в нём есть токен, поэтому журнал не публикуйте.
- Авторизации нет: любой, кто может подключиться к порту 9091, способен менять остатки и добавлять принтеры. На тестовом компьютере не открывайте этот порт для сети.
- Список зависимостей проекта лежит в файле `go.mod`.
